# Pipeline bug sweep, 18 Nov 2026

This was a read-only review of the whole pipeline, done by four reviewers working in parallel:

- the archive mirror and downloads;
- photometry up to the per-frame calibration;
- the ensemble stage and orchestration;
- spectroscopy and the website.

Each bug below was reproduced offline or traced in the code. The main ones were checked again in the code before
this list was written. Nothing has been fixed yet.

Status key: **open** = not fixed; **QC** = in the scope of the frame-QC session (QC-000x numbering).

## High

| # | Area | Where | Bug | Failure scenario |
|---|---|---|---|---|
| 1 | lcodb | `ava/lcodb/api.py:96-108`, `ava/lcodb/headers.py:43-46` | HTTP 500/502/503/504 is retried 7× with backoff. `headers.fetch` then marks the frame `-1` and moves to the next one; only a 429 stops the step. | Server-wide 500s during a header backlog → 4 workers × 7 requests per frame ≈ 12,800 requests/day, over the 5000/day account limit. This breaks the "a repeated 500 is not transient" rule. |
| 2 | ensemble | `ava/pipeline/tasks/ensemble.py:46` | `IC.intercalibrate` returns a frame with no columns when no camera has a fit, so `table["scope"]` raises `KeyError`. | A target with a single camera, fewer than 10 overlap nights, or MuSCAT only. The solutions and `agn_lightcurve_pytics.parquet` are already rewritten (without `mag_ic`/`F_ic`), but the merged CSV, F_var and the plots are never made. It fails every night. |

## To confirm (not verified, or a decision)

- `pipeline.prefect.nightly_steps` (`config/ava_config.yaml:578`) does not include `pytics`. As configured, the nightly run never
  updates the ensemble light curves.
- `merge` raises `NotImplementedError`, so `-m`/`-s` fails for every target.
- AVA reads the lcodb config from `cfg.lcodb_config_path` (`ava/config.py:248`) and ignores `LCODB_CONFIG`.
- Cleanup frees a standard only by its own night name (`ava/archive/cleanup.py:291-294`), so it can delete a standard that an
  unreduced night elsewhere still needs (related to 3).
- Signed S3 URLs (valid 48 h, not the token) appear in download error messages and logs.
- The spectra `Query.keep` has no instrument check (a SOAR spectrum under the same target name would be kept).
- `arm_offsets` keeps stale offsets and template after `align_*` config changes (nothing passes `rebuild=True`).
- `errors.fit_s_cam` `brentq(f, 0, 0.5)` raises if no root is found below 0.5 mag.
- `colour_term_check` uses `min_pairs=10`, not `intercal_min_pairs`. `run_target` hard-codes `lco_g - lco_i`.
- fa08 `up`: 0 of 172 frames get a zero point (0.8 candidate standards against about 13). It could be hardware or a U/up label problem.
- Stars with NaN RUWE pass `quality_ok`.
- `ava_stats()` in `web/` sums over all of `agn_lco` without the target filter. It matches today only because the excluded targets have 0 frames.

## Checked and correct

- Science aperture per camera and catalogue series (fa/fl 27 px, fs 33 px, ep 39 px with 16 apertures, kb 21 px).
- Exposure-time normalisation and the GSPC AB offsets.
- Colour-term signs across `fit` / `update` / `apply`, and c0 against c0′.
- `update()` applying the star×scope offsets and `CK`; a new scope triggering a refit.
- `mag_err` against `mag_err_rand` in the merged CSV.
- Plot serialisation.
- PHP input validation, SQL parameters, path checks and HTML escaping.
